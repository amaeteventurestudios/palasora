# Implementation decisions (ADR log)

Each entry: decision, why, rollback. "[Default]" means an implementation default, not a founder decision.

## ADR-001 Mac-native services, Compose for later [Default]
Colima's Docker works, but it runs x86_64 with about 5.8 GiB of RAM, and `buildx` is missing. Fast iteration and honest measurements are easier natively: Next.js, PocketBase and FastAPI run as loopback processes started by `scripts/dev-up.sh`. Dockerfiles and `infra/compose/docker-compose.yml` are provided and tested where feasible (Phase 5). **Rollback:** use Compose instead; no code change needed.

## ADR-002 Ports [Default]
Web `127.0.0.1:3000`, PocketBase `127.0.0.1:8190`, editorial `127.0.0.1:8100`. 8090 and 3100 belong to unrelated apps on this Mac.

## ADR-003 OpenMolt: Path B
See `DECISION-OPENMOLT.md`.

## ADR-004 PocketBase access model
All Palavva collections have `null` API rules (superuser only) except where noted, so **anonymous and user-token access straight to PocketBase is denied**. The Next.js server is the sole PocketBase client and authenticates as a dedicated service superuser (`PB_SERVICE_EMAIL`), held only server-side. Tenant checks live in one repository module (`apps/web/lib/repo/*`), and every query includes `tenant_id = <host-resolved tenant>`. **Why:** PocketBase rules can't express host→tenant binding, because the browser never talks to PB. **Defense in depth:** `pb_hooks` reject any write that turns an `editorial_pieces` record `published` unless `reviewer_id` and an `editorial_reviews` approval exist, and reject `tenant_id` changes on update. **Rollback/migration:** the repository interface is the seam for a later PostgreSQL move.

## ADR-005 Sessions [Default]
Password auth is verified by PocketBase (`users` auth collection, bcrypt). On success Next.js creates an opaque random session (32 bytes; only its SHA-256 is stored in `sessions`), bound to `tenant_id` and `user_id`, with a 14-day expiry, in an `HttpOnly; SameSite=Lax` cookie (`Secure` when served over HTTPS). Mutations require a same-origin check (Origin/Host) plus a per-session CSRF token for form posts. A session from tenant A is rejected on host B.

## ADR-006 Email: local mail sink [Default]
No SMTP. Verification and notification emails are written to `data/mail-sink/*.eml`, and the admin can view them at `/admin/settings`. No real email is ever sent.

## ADR-007 Search: FTS5 sidecar in the editorial service [Default]
`data/search.db` (FTS5), indexed per tenant at publish time. Next calls `GET /search` on the editorial service server-side. If the editorial service is down, Next falls back to a bounded PocketBase `~` filter over published pieces only.

## ADR-008 Job queue
SQLite `data/jobs.db` with tables `jobs`, `job_attempts` and `dead_letters`, using the fields from `09`. Claims are transactional with a lease, 3 attempts, jittered exponential backoff and a unique idempotency key. One process owns the file.

## ADR-009 Analytics [Default]
`POST /api/v1/analytics/events` → allowlisted, PII-stripped → `data/analytics/tenant=<id>/date=<d>/events-<hour>.ndjson`. The ETL (`services/editorial/analytics_etl.py`, DuckDB `read_json_auto`) writes daily aggregates into PocketBase `aggregated_metrics`. Parquet conversion is deferred: NDJSON is directly queryable by DuckDB, and the conversion adds no MVP value. **Rollback:** add `COPY … TO parquet` in the ETL.

## ADR-010 Content on the platform tenant while no source is approved [Default]
`01` PR-001 allows "clearly marked sample content or a real empty state". When `SHOW_DEMO_CONTENT=true` (local default), a small set of clearly labeled **Demo content** fixtures is visible on the platform tenant. They carry `is_demo=true`, a visible `Demo content` badge, `noindex` and sitemap exclusion, use non-political, obviously fictional framing and point sources at `example.invalid`. Setting `SHOW_DEMO_CONTENT=false` gives the real empty state.

## ADR-011 Editor approval of real AI drafts
The agent does **not** approve its own AI drafts of real news. Drafts generated by real Qwen from real source items wait in the editorial queue for the founder or an editor. Automated E2E approval tests run against fixture items with the deterministic fixture provider.

## ADR-012 SSRF residual risk: DNS rebinding [Default]
Every fetch hop's DNS answers are validated (no loopback/private/link-local/CGNAT/metadata), redirects are followed manually and re-checked, hosts are allowlisted per source. httpx performs its own DNS lookup after our check, so a rebinding window remains. **Accepted for allowlisted publisher hosts in local dev.** **Fix before public launch:** pin the connection to the validated IP (custom transport) or run fetches in an egress-restricted container.

## ADR-013 Prompt clarifications after observing real Qwen (researcher-v2, writer-v2)
With v1 prompts, real `qwen3.5:4b` abstained on 9/10 researcher calls and 8/8 writer calls, even when the permitted excerpt clearly supported claims. v2 adds explicit statements: the publisher's permitted excerpt **is** citable evidence; a publication date is not an event date; the writer must draft when verified claims exist and must attribute government statements. Validation gates are unchanged (claim IDs must resolve; numbers/quotes checked; risk routing). Versions and hashes are stored in `ai_runs`. **Rollback:** revert `prompts.py` VERSIONS.

## ADR-014 Feed micro-cache (5 s, per tenant+filter) [Default]
The load test showed Next SSR CPU as the bottleneck. The published-feed candidate list is cached in memory for 5 s, keyed by the full filter string (which contains the tenant ID). Publish/correct/retract/vote/comment actions invalidate it. Drafts are never cached. Home throughput rose from ~49 to ~68 req/s at c=10, and p95 fell from 302 to 192 ms.

## ADR-015 Auth navigation does a full page load
E2E tests showed that a Server Action `redirect()` after sign-in rendered the destination **inside the action response** with the old cookie state, losing the `next` path and sometimes the tenant's layout. Now, with JS, the action returns the destination and the client performs a full navigation (forcing a reload when only the `#hash` differs); without JS, it still sends a 303.

## ADR-016 Overnight AI quota change (audited)
Tenant quota `daily_ai_requests` went from 60 to 100 (audit event `tenant.quota_changed`) and `MODEL_DAILY_REQUEST_BUDGET=100`, so the remaining real SAnews clusters could be drafted for founder review. Concurrency stays 1 (enforced by a worker `flock`). Total real calls tonight: 74. **Rollback:** set both back to 60 in Command Center/env.

## ADR-017 RATE_LIMIT_SCALE for the isolated E2E stack only
All E2E traffic comes from one loopback client, so the test stack sets `RATE_LIMIT_SCALE=50`. Dev and production default to 1. Limiter behavior is unit-tested.

## ADR-018 Source rights approval by the agent is provisional
SAnews.gov.za was approved for **local development ingestion** based on its published user policy (see `sources/SANEWS-RIGHTS-REVIEW.md`), with `rights_verified_by = "build-agent (pending founder/legal confirmation)"`. All other candidates remain `pending` and disabled. Nothing from SAnews has been published; the drafts await an editor.

## ADR-019 Single worker process
A model concurrency of 1 must hold across processes. The worker takes an exclusive `flock` on `data/run/worker.lock` and exits if another worker holds it (found when a stale pid file left two workers running).
